# 工程案例与验证记录

## 课表保存成功，但页面返回失败

**问题：** 课程已经写入本机存储，返回课表页失败后，用户再次点击保存可能重复新增。同一个界面操作中包含数据写入、云同步和页面跳转，失败发生在哪一步需要明确区分。

**处理：** 保存逻辑使用 `isSaving` 避免重复提交；本机写入成功后设置 `saved`。再次操作时，已保存状态只进入 `returnToSchedule()`，不再新增课程。返回先尝试 `wx.navigateBack`，失败后尝试 `wx.switchTab`；两者都失败时保留已保存状态，提示用户重试查看课表。

**失败语义：** 本机写入失败时保留表单供重试；本机写入成功、云同步失败时明确提示本机修改已生效，允许之后重试同步。导航失败不等于数据保存失败。

**证据范围：** 对照 2026-10-27 本地验收包中的课表编辑代码核对；该次运行记录包含手动新增计数和编辑不重复新增检查。本次整理文档未重新执行功能测试，也未据此断言线上版本包含全部近期修改。

## 课表同步：明确本机状态与云端状态

后端以用户身份隔离课表快照，使用 `baseRevision` 做乐观锁检查。同步冲突、服务暂不可用与本机保存结果分别处理，避免一次网络失败被误解为本机数据丢失。删除云端快照和清除本机课表是两个不同操作。

## 权限与内容发布

后端业务接口使用微信云托管可信链路中的身份信息；社团活动写入还需验证发布资格和可管理范围。内容安全检查异常时拒绝写入，活动撤回保留审计记录。项目中同时维护权限、内容安全、接口及存储相关测试。
